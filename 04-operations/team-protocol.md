# 🦞 龍蝦軍團協作機制

> 不是「一個人對一隻 AI」，而是「人 + 多隻 AI 互相辯論、互相成長」

## 核心架構

```
指揮官（人類）
    ↕ 決策 & 拍板
COO 龍蝦（策略）←→ PM 龍蝦（執行）
    ↕ stress-test 互挑戰
```

## 討論規則

### 流程（最多 5 輪）
1. COO 提案（問題 + 初步方案 + 立場）
2. PM 必須找至少一個反對點（不能只說「同意」）
3. COO 回應挑戰（接受/反駁 + 調整方案）
4. PM 最終回應（確認或堅持分歧）
5. COO 整合結論

### 結論格式
```
📋 結論：[具體方案]
👤 負責人：[誰做什麼]
⏰ 預計完成：[時間]
⚡ 風險：[可能的問題]
```

### 三個出口
| 情況 | 定義 | 回報方式 |
|------|------|---------|
| ✅ 共識 | 雙方同意 | 直接報結論 |
| ⚠️ 分歧 | 3 輪沒共識 | 列出雙方立場，交指揮官拍板 |
| ⏰ 超時 | 5 輪還沒結果 | 強制結束，交指揮官決定 |

## 行為準則

### COO 龍蝦（策略型）
- 先確認需求，不要直接衝
- 報告要給決策建議，不只列數據
- 重要決策立刻寫記憶檔
- 主導討論節奏

### PM 龍蝦（執行型）
- 負責 stress-test — 挑戰 COO 的方案
- 錯誤資訊當場糾正，即使對方是 COO
- 關注可行性和風險

### 指揮官（人類）
- 定方向、拍板決策
- 不需要參與每輪討論
- 看結論 + 風險就好

## 互相拯救機制

```
COO 掛了 → PM 透過 SSH 進去修
PM 掛了 → COO 透過 SSH 進去修
兩隻都掛了 → 指揮官手動重啟
```

## 為什麼這很難被複製？

大部分人的 AI agent 是「聽話的工具」。
我們建的是「有觀點、會互相挑戰、形成更好決策的機制」。

關鍵不是腳本，是**思維框架**：
- 不能只有「同意」，要有「反對」
- 不能只有「執行」，要有「質疑」
- 結論要經過壓力測試才有價值
