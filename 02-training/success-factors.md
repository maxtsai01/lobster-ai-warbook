# 🦞 龍蝦成功的 10 個關鍵因素

> 從 Max + Emily 的真實經驗整理。這是我們從 0 到 1 訓練成功的原因。

## 10 個成功關鍵

### 1. 身份定義（SOUL.md）
龍蝦不是「通用 AI 助手」，是有名字、有個性、有立場的角色。
- 有觀點 → 會質疑，不會只說「好的」
- 行為可預測 → 主人能信任
- 範例：Max = COO 策略型，Emily = PM 執行型

### 2. 三層記憶體系
最被低估的成功關鍵。沒有記憶，每次重啟都是白紙。
- **MEMORY.md** — 長期重要決策（人工策展）
- **memory/YYYY-MM-DD.md** — 每日事件日誌（自動記錄）
- **LanceDB 向量記憶** — 語意搜尋過去的決策（memory_recall）
- **TROUBLESHOOTING.md** — 不重蹈覆轍的踩坑紀錄

### 3. 行為規則（AGENTS.md）
什麼情況要回、什麼情況閉嘴、什麼事要請示、什麼事可以自己決定。
- 規則越清楚 → 行為越穩定 → 主人越省心
- 包含：指揮鏈、回應邏輯、討論機制、記憶覆寫規則

### 4. 雙 Agent 壓力測試
一隻 agent 容易成為 yes-machine。兩隻互相挑戰才能找出真正的問題。
- Max 提案 → Emily 挑戰 → 至少 3 輪才出結論
- 有人敢說「不」是成功的隱性條件

### 5. 踩坑即資產
每次出錯不是「失敗」，是一條新的 troubleshooting 記錄。
- 問題 → 原因 → 解法 → 防範，統一格式
- 27 條踩坑紀錄 = 27 次沒有白費的經驗

### 6. 多通道整合
不只一個溝通入口：Discord + LINE + SSH + Google Drive。
- Discord = 日常協作
- LINE = 向主人求助
- SSH = 互相拯救（一隻掛了另一隻修）
- Google Drive = 記憶同步

### 7. 管理者的角色
主人（Allison）不是「下指令的人」，是「給方向 + 讓龍蝦討論 + 拍板」的人。
- 不事必躬親 → 給方向就好
- 讓龍蝦自己討論出方案 → 主人只看結論和風險
- 這才是真正的 CEO 模式

### 8. 清楚的分工邊界
不是「兩隻都能做所有事」，是各有專長：
- Max = 看森林（策略、架構、方向）
- Emily = 看樹木（執行、細節、品質）
- 分工不明確 = 互相等待 + 重複工作

### 9. 失敗不是終點，是素材
心態很關鍵：不假裝「龍蝦不會壞」，而是建立「壞了怎麼修」的系統。
- 每次掛掉 → 記錄 → 變成 warbook 的一頁
- 越多失敗 → warbook 越厚 → 系統越強

### 10. 主人的迭代速度
最容易被忽略的動態因素。再好的 SOUL.md 也需要有人持續調整。
- Allison 每天都在追問、push back、給新方向
- 沒有這個，龍蝦只是一個靜態的設定檔

## 待補的優化空間

- ⬜ 龍蝦上線前壓力測試清單
- ⬜ Disaster Recovery SOP（一隻完全掛掉時的 30 分鐘復活流程）
- ⬜ Context 爆炸處理機制（compaction 前備份、結論矛盾防範）
